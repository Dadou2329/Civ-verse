# Narrative traceability — scenarios → implementation

This document maps every requirement of the two narrative specifications to the content and
code that implement it, the automated test that exercises it (if any), and an honest status.

- `docs/narrative/DOOR_CIVILIZATION_SCENARIO.txt` — dossier 001, « La Porte qui n'existe pas »
  (pack `civilizations/door`).
- `docs/narrative/MEMORY_CIVILIZATION_SCENARIO.txt` — dossier 002, « Le Nom qu'on t'a volé »
  (pack `civilizations/memory`).

The scenarios are written in French. Requirements below are summarized in English and quote the
French key phrase. Section numbers (§) are those of the scenario files.

Verified against commit `7b2aa0a` (2026-10-12); rows affected by later changes were updated up to
commit `0f92dd7`. French texts are quoted as they appear in the locale tables, which use
typographic apostrophes and no-break spaces (see [`../LOCALIZATION.md`](../LOCALIZATION.md)).

## How to read the tables

**Paths.** In section 1, paths are relative to `civilizations/door/`; in section 2, to
`civilizations/memory/`; paths starting with `src/`, `docs/`, `tests/` or `civilizations/` are
relative to the repository root. Content ids are the ids used in the JSON files: entity ids of `content/scenes/*.scene.json`,
dialogue nodes as `dialogue/node` (`content/dialogues/<dialogue>.dialogue.json`), quest, stage and
objective ids, cinematic ids, logic rule ids (`content/logic/*.logic.json`), localization keys.
The scene JSON files are the runtime source; they were generated by the seed scripts
(`seed/*.ts`, used here as the readable description of the world layout) and then edited in the
Studio.

**Verified by.** Test cases of the headless playthroughs. They walk with A* at the player's size,
interact through the game's interaction pipeline, answer dialogues, skip every cinematic, save and
reload.

| Label | File | Test name |
| --- | --- | --- |
| D1 | `civilizations/door/tests/door.playthrough.test.ts` | « main path: testimony of Mira, then listening to Varen » |
| D2 | same | « alternate path: forged report, opening at once » |
| D3 | same | « the patrol escorts an intruder out, three times, then Varen summons the player » |
| D4 | same | « the evidence persists through a save and a reload » |
| M1 | `civilizations/memory/tests/memory.playthrough.test.ts` | « help path, honest player: Silas accepts the restoration » |
| M2 | same | « trade path, a comforting lie: Silas refuses, and they meet as strangers » |
| M3 | same | « Léa refuses when the restoration is imposed; the Door civilization leaves its trace » |
| M4 | same | « honesty is not enough without trust: an honest answer after earlier lies still gets a refusal » |
| M5 | same | « shards, slots, the puzzle and the choices persist through a save and a reload » |

Coverage of the Door tests: D1–D4 play the prologue and Act I; D1, D2 and D4 play Acts II–III
(D4 after a reload); D3 stops once Varen grants access. Coverage of the Memory tests: M1–M5 play
the prologue, Act I and Act II; M1, M2, M3 and M5 play Act III and the dénouement; M4 stops at the
consent scene.

`manual/visual` means the requirement can only be judged by a person (rendering, feel, writing
quality, timing). `none` means no automated test asserts it; the evidence is the cited code or
content. Some rows also mention the acceptance tests in `tests/acceptance/` in the Notes column.

**Status.** *Implemented*: present in the shipped content or code and reachable in play.
*Partial*: present but incomplete, unreachable in play, or covering only part of the requirement.
*Not implemented*: no code or content found. Deviations from the letter of the scenario are listed
in Notes even when the status is *Implemented*.

Play time (« 25 à 40 minutes », act durations) is not measured anywhere in the repository: no timed
playtest, no telemetry. The tests skip cinematics, so they say nothing about duration.
